## 1. 结论摘要

推荐采用 **原生 TypeScript、局部透明 Canvas 2D、二维骨架与接触约束、DOM 分层识别、平台相对锚点、预算化增量调度**。

首版默认一个人物、无运行时第三方依赖、无截图或联网识别。五个原始示例场景全部作为首版验收范围，不能用少量固定平台的演示替代通用页面识别。

“任意可见元素”应理解为产品的识别覆盖目标，而不是浏览器提供了任意绘制内容的完整轮廓接口。首版对常见 DOM 绘制提供自动识别，对复杂绘制提供扩展接口，对浏览器安全边界明确报告限制。

调研确认的关键事实：

1. DOM 几何读取必须在主线程进行；Worker 不能访问 DOM，DOM 节点和函数不能通过 structured clone 传送。[S09][S10]
2. 文本 Range 矩形基于字体度量和排版宽度，不是实际字形墨迹轮廓；空格也可能有矩形宽度。[S01]
3. `elementsFromPoint()` 是命中测试结果，不是像素绘制清单；透明命中盒与 `pointer-events: none` 的可见覆盖层会带来相反方向的误判。[S03][S04]
4. IntersectionObserver 主要用于交集与发现，不能默认提供精确遮挡判断；`checkVisibility()` 也不等于“用户当前能看见”。[S05][S06]
5. 移动端布局视口与可视视口不同；缩放、软键盘和滚动必须分别处理。[S07]
6. 高 `z-index` 不能越过浏览器 top layer。模态对话框、popover 和 fullscreen 需要明确的覆盖层策略。[S24]

## 2. 动画与渲染方案比较

| 方案 | 风险与性能边界 | 内存特征 | 流畅衔接与扩展 | 推荐结论 |
| --- | --- | --- | --- | --- |
| 精灵帧动画 | 绘制简单，但效果依赖美术资源；不能直接在任意两帧间求真实姿态 | 图集解码、纹理与多分辨率资源可能明显大于线条人物 | 追加动作需要新资源；形状改变和足部约束困难 | 保留皮肤扩展方向，不作为默认方案 |
| 小型 Canvas 2D 实时骨架 | 局部重绘，避免逐关节 DOM 更新；仍受主线程长任务影响 | 主要为小画布缓冲和少量骨架数据 | 可混合姿态、参数化比例、增加程序动作、实现 IK | 默认方案，须与小型 SVG 原型实测比较 |
| SVG 骨架 | 少量节点可能很轻量；几何变化仍可能需要重绘，不能假定所有 SVG 动画只走合成线程 | 少量 DOM 节点，无全屏像素缓冲 | 便于矢量皮肤和关节分组；同样需要接触约束 | 备选渲染器，不预先断言比 Canvas 慢 |
| CSS / WAAPI | `transform`、`opacity` 有机会被浏览器离主线程采样；动态碰撞与支撑重定位仍需 JS | 少量节点时低；大量关节动画对象需要管理 | 固定待机、淡入可用；复杂物理运动不能只靠关键帧 | 不作为根运动与碰撞的唯一驱动 |
| WebGL / PixiJS | 大量角色、纹理、特效可受益；一个线条人物不值得默认承担渲染器复杂度 | GPU 资源、批次、纹理及上下文需要显式释放 | 适合后续大量角色或粒子效果 | 首版不引入 |
| OffscreenCanvas | 是 Canvas 的线程部署方式，不是另一套动画模型；不能解决主线程 DOM 跟随问题 | 增加线程、消息及缓冲管理 | 可复用姿态数据，但时序同步更复杂 | 仅在实测绘制成为瓶颈后评估 |

依据：[S11]—[S15]、[S29]。本节记录编码前的调研判断；首阶段的小样本实测见实施与验收计划第 12 节，正式大页面与真机基准尚未完成，不能据此给出普适性能排名。

### 2.1 画布大小与内存

默认只创建覆盖人物动作包络的小画布，不创建全屏 Canvas。画布宿主通过 `transform` 移动，内部骨架在局部坐标绘制。

单个 RGBA 像素缓冲的计算下界：

`逻辑宽度 × 逻辑高度 × DPR² × 4 字节`

- 96 × 96 CSS px、DPR = 2：约 144 KiB。
- 1920 × 1080 CSS px、DPR = 2：约 31.6 MiB。

这不是浏览器实际总内存：多重缓冲、合成纹理、JS 堆和观察器还会额外占用内存。默认 DPR 上限暂定为 2，最终由清晰度与真机测试决定。动作包络在初始化、外观变化或注册新动作时计算，不每帧改变画布 `width` / `height`。[S12]

### 2.2 连贯动画的决定性因素

渲染技术不能单独保证动作自然。需要拆开三个职责：

- **根运动**：运动学、重力、碰撞与平台跟随决定人物的位置。
- **行为状态**：决定走、跑、起跳、坠落、攀爬、坐下等语义。
- **姿态求解**：骨骼采样、姿态融合、FK、两段腿或手臂 IK，以及脚、手、臀部接触约束。

切换从“当前已求解姿态”开始，不从旧动作首帧重新开始。走跑按相对支撑面的行进距离推进步态；滚动与平台载体位移不能计入步幅。支撑消失立即解除接触，不等待坐姿或挥手动画播放完成。

碰撞冲量、元素瞬间布局变化和边界循环可能有意产生位置或速度不连续，不能承诺所有情况下数学上的全程连续。

## 3. 页面识别方案比较

| 对象或技术 | 可自动获得的证据 | 无法直接保证的部分 | 首版策略 |
| --- | --- | --- | --- |
| 可见边框 | 布局盒、边框宽度、样式与颜色 | 复杂圆角、装饰、旋转后的真实边缘 | 抽取已知平直边段；排除圆角端部 |
| 纯色背景块 | 背景色、alpha、布局盒和已知背景链 | 图片、渐变、滤镜、混合模式下的真实底色 | 已知纯色做感知色差判断；未知不伪造颜色证据 |
| 文字 | Text 节点、Range 分片、字体与排版信息 | 实际字形墨迹、连字细节、所有文字方向的物理平台 | 支持水平排版片段；局部细化空格和指定标点 |
| hover / focus 高亮 | 交互事件与重测后的 computed style | CSS 变化不一定产生 DOM mutation | 当前支撑优先重测，交互后局部刷新 |
| SVG 线条与矩形 | 简单几何、fill / stroke、坐标变换 | 任意 path、mask、滤镜的真实轮廓 | 自动支持简单水平/垂直线段与轴对齐矩形边段 |
| 图标 | 字体片段、简单 SVG 或元素外框 | 图片透明区域与复杂路径内部轮廓 | 按实际来源处理，不把所有图标矩形都当实体 |
| 图片、Canvas、WebGL、视频 | 元素外框与明确外边框 | 绘制内容内部的对象、透明洞、运动平台 | 默认只识别可靠外边框；内部交给 SurfaceProvider |
| `elementsFromPoint()` | 局部命中栈、辅助发现 | 非命中测试绘制、透明盒、窄遮挡 | 辅助证据，不作为唯一发现或可见性判断 |
| IntersectionObserver | 视口附近容器与交集变化 | 精确像素、所有遮挡、每帧安全落点 | 用于粗筛，不用于最终碰撞判定 |
| open Shadow DOM | root、slot 和可访问节点 | 普通根观察器不会自动观察所有 shadow 子树 | 显式纳入组合树遍历，分别观察各 root |
| closed Shadow DOM | 宿主外框 | 内部结构不可通过普通 `shadowRoot` 获得 | 组件主动提供 root 或几何适配器 |
| iframe | iframe 外框；同源时可访问文档 | 默认不能跨 frame 使用内部命中栈；跨域受同源策略限制 | 首版默认识别外框；内部独立实例或后续适配器 |
| 截图 / 视觉模型 | 已授权截图中的视觉候选 | 稳定元素身份、实时准确碰撞、免费无权限截图 | 非默认、非首版交付；只设计扩展边界 |

### 3.1 推荐识别链路

采用“增量发现 → 几何与绘制证据 → 裁剪及局部遮挡校验 → 周围文字精化 → 可达性筛选”。

扫描优先级为当前支撑、正在执行的目标、预计落点、前进方向、邻域、较远的可视区域。不能每帧遍历整个页面，也不能一次性给所有文字字符创建持久 Range。

每个平台必须同时记录：来源身份、几何类型、证据强度、有效性、几何版本、所属运动参考系。**几何矩形存在不等于可站立，当前可见不等于当前可达。**

### 3.2 “可区分背景色”的定义

不使用一个未经说明的“颜色差异百分比”。推荐对能够可靠解析的 sRGB 纯色及 alpha 合成结果使用 OKLab 感知色差；阈值作为可调启发式，由场景测试校准，不套用 WCAG 文本对比度作为物理平台标准。

只有已知底色链才能计算此证据。背景图片、渐变、混合模式、未知透明层或复杂色域无法可靠解析时，颜色证据为 `unknown`，不得假定页面背景一定为白色。可用明确边框、文本或宿主几何证据补充。

### 3.3 可见性的精度声明

沿支撑线做有限采样，只能得到局部近似，仍可能遗漏窄遮挡。平台脚下的可见性与人物身体的可用空间应分别检查。

首版不宣称“逐像素识别所有元素”或“遮挡判断百分之百准确”。遇到不可靠复杂几何，宁可不生成平台，也不能从外接矩形猜出不存在的地面。对无法确认的当前支撑先暂停新的主动动作并优先重测；对明确失效的支撑立即坠落。

## 4. 后台计算与性能决策

首版默认主线程预算化处理，原因是一个人物的局部几何与短程动作规划规模通常有限，而 Worker 的复制、排队、线程资源和版本同步不是零成本。

必须放在主线程的工作：DOM 遍历、Range、computed style、几何读取、事件接入、观察器和覆盖层位置更新。

可以后续交给 Worker 的工作：纯数值空间索引、较大局部图的路线搜索、批量候选评分。只发送数值快照及不含 DOM 的身份 ID；结果必须绑定 scene / frame / 请求版本，落地前由主线程重新校验。

不发送完整 DOM，不发送页面文本，不传送插件函数。Worker、OffscreenCanvas、SharedArrayBuffer 均不作为默认前提；不要求宿主增加跨源隔离响应头。[S09][S10][S15]

主线程忙碌时，即使 Worker 继续计算，也无法保证人物正确跟随正在变化的 DOM。目标是低开销、可降级、过期结果不会破坏正确性，而非对任意宿主负载承诺恒定 60 FPS。

## 5. 推荐决策表

| 编号 | 推荐决策 | 主要理由与代价 |
| --- | --- | --- |
| D01 | 原生 TypeScript，默认无运行时依赖 | 框架无关、接口明确；需要自行实现小规模骨架与运动算法 |
| D02 | 局部 Canvas 2D，渲染器接口独立 | 控制绘制面积；不是主线程阻塞的万能解法 |
| D03 | 单人物，24 个动作定义、20 类预置触发 | 将“大量预置”转换为可验收数量；多人物不在首版性能承诺中 |
| D04 | DOM 分层识别 + SurfaceProvider | 常见页面自动接入，复杂绘制不侵入宿主 |
| D05 | 客户端坐标快照 + 平台相对锚点 + 运动参考系 | 同时解决嵌套滚动、固定元素和空中滚动，不重复补偿滚动量 |
| D06 | 默认保留滚动离屏的相对锚点 | 满足相对位置保持；离屏期间可能暂时看不到人物 |
| D07 | 边界循环由人物自身运动触发 | 滚动、键盘弹出或缩放不误触发传送 |
| D08 | 增量预算调度，Worker 后续按实测接入 | 简化首版资源与通信；大型页面仍需限额和降级 |
| D09 | 显式注册算法文件，不运行时扫描目录 | 适用于浏览器和 tree shaking；新文件需加入静态注册清单 |
| D10 | 默认交互透传，不修改宿主元素 | 不阻断按钮、文本选择和滚动；人物点击通过几何命中判断 |
| D11 | 默认不截图、不联网、不保存页面内容 | 保持隐私和离线能力；视觉增强需要另行批准 |
| D12 | top layer 默认避让，特殊层由宿主提供挂载点 | 不擅自抢占模态层或改变 fullscreen 行为 |

## 6. 范围与待确认事项

### 6.1 首版必须完成

常见水平 DOM 平台、文字空格/指定标点、纯色背景与边框、简单 SVG 线段、open Shadow DOM、嵌套滚动、动态支撑失效、五个示例、骨架动画、扩展注册、属性设置、交互透传、页面循环、生命周期与单页示例。

### 6.2 不自动纳入首版

任意 SVG path 轮廓、3D / perspective、任意 clip-path / mask、图片/Canvas 内部自动视觉识别、跨域 iframe 内部统一世界、Worker 路线规划、OffscreenCanvas、多人物、具体框架包装包、远程视觉模型实现。

这些不是已经实现的隐藏功能。需要时通过明确的后续需求接入，不发布空实现或假装可用的入口。

### 6.3 当前实施基线与发布前事项

经编码计划批准，当前按以下基线分阶段实施：

1. 常见 DOM 自动识别，复杂绘制通过适配器扩展。
2. 默认 Canvas 2D 骨架；首阶段已用同一 Pose 做小型 Canvas / SVG 对照，保留 Canvas 决策。
3. 完整首版目标为单人物、24 个动作定义和 20 类触发；当前仅交付首个闭环子集。
4. 滚动离屏时保留锚点，不为始终可见强制重生。
5. 截图和远程视觉服务默认关闭，不在首版实现范围。
6. 许可证已由用户明确选择 MIT；npm 名称 `mono-stickfigure` 的占用与正式发布仍需在发布前核验，当前保持未发布。

确认文档仅授权后续约定范围的本地编码与测试，不自动授权 npm 发布、上传截图、调用收费服务或远程操作。

## 7. 风险与验证方式

| 风险 | 应对方式 | 验证门槛 |
| --- | --- | --- |
| DOM 外框被误当成真实实体 | 要求绘制证据，区分未知与失效，复杂形状走适配器 | 透明容器、圆角、图片透明区不能生成虚假平台 |
| CSS 动画或 hover 改变平台但没有 DOM mutation | 当前支撑每帧优先校验，局部交互/动画刷新 | 纯 CSS 高亮消失、平移、折叠均不悬空 |
| 高密度页面识别压垮主线程 | 预算分片、局部精化、缓存上限、合并失效 | 大页面压力测试与宿主基线对比 |
| 姿态融合后脚滑或动作穿透 | 距离驱动步态、接触锁、IK、扫掠碰撞 | 慢速录屏与自动几何断言 |
| 祖先 transform 改变 fixed 挂载参考系 | 校验挂载点，明确支持的二维范围 | transformed root、嵌套滚动与缩放专项测试 |
| 页面导航或实例销毁残留资源 | 独立 disposer，释放节点、引用、观察器和任务 | 重复创建/销毁与堆快照 |
| 默认覆盖层无法进入 top layer | 避让或宿主挂载适配，不滥用最大 z-index | dialog / popover / fullscreen 测试 |
