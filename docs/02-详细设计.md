## 1. 架构原则与不变量

首版采用 TypeScript、局部 Canvas 2D、固定拓扑二维骨架、单人物和主线程预算化调度。DOM 识别和数值运动分离，不依赖业务框架、完整游戏引擎或远程服务。

必须保持以下不变量：

1. 同一实例只有一个活动调度循环和一个根运动写入者。
2. DOM、样式、Range 和事件在主线程处理；数值运动与姿态模块不引用 DOM。
3. 几何存在、可见、可站立、可达是四个不同判断。
4. 支撑明确失效立即解除接触；随机行为和扩展不能推迟该规则。
5. 页面载体运动、人物主动运动和姿态内的身体偏移分别计算，不重复叠加。
6. 姿态片段不能自行设置世界位置；IK 不能通过任意拉长骨段弥补不可达接触。
7. 当前帧只使用已经提交的几何快照；跨版本的异步结果不能直接覆盖运动状态。
8. 装饰层默认交互透传，不改变宿主文本、布局、焦点或滚动。
9. 缓存、观察目标、事件队列和扫描任务有界；不知道不等于不存在。
10. 暂停原因彼此独立，释放一个原因不能撤销另一个原因。

## 2. 模块与依赖

### 2.1 数据流

```text
宿主 DOM / Pointer / CSS 状态 / SurfaceProvider
                 ↓
     输入归一化 + 失效队列 + 几何读取
                 ↓
     绘制证据 / 裁剪 / 遮挡 / 平台快照
                 ↓
        局部索引 → 行为候选与可达性
                 ↓
      安全仲裁 → 根运动 / 碰撞 / 接触
                 ↓
       骨架采样 → 融合 → FK / IK
                 ↓
        小型 Canvas 绘制与宿主定位
```

浏览器事件只记录事实和标脏，不在每次 scroll / pointermove 中立即扫描、规划、绘制。每个阶段具有单向输入输出，避免动画模块反向查询 DOM。

## 3. 数据模型

### 3.1 身份、版本与所有权

- `SourceId`：实例内部来源 ID。DOM 节点通过 WeakMap 分配；无 DOM 的对象由 Provider 的稳定 key 映射。
- `sourceRevision`：逻辑身份/内容代次。文字变化、虚拟列表换项或 Provider 替换实体时递增。
- `SurfaceId`：来源中的稳定几何特征，例如某条边或某段文字；不使用屏幕坐标作 ID。
- `geometryVersion`：同一特征的位置、长度或可用区间改变时递增。
- `sceneVersion`：已经提交的场景变更序号。
- `frameId`：本次读取与模拟的快照序号，不等于浏览器全局帧号。

同一节点仍然存在，不证明它仍代表同一个虚拟列表项目。自动识别可根据内容变更使特征失效，但无可观察变化的业务身份必须由 Provider 主动更新。

源表只在主线程持有有限 DOM 引用。传入 motion / behavior 的快照只含 ID、数值、枚举和区间；不传入 Element、Text、Range 或回调。

### 3.2 核心记录

| 记录 | 必需字段与语义 |
| --- | --- |
| `SurfaceSnapshot` | ID、来源代次、几何版本、种类、两个端点、法线、可用参数区间、能力标记、证据、参考系 ID、状态、测量时间 |
| `Anchor` | SurfaceId、sourceRevision、特征参数 `u`、接触角色、离开表面的法向偏移；脚/手/臀可各有锚点 |
| `FrameSnapshot` | frameId、时间、可视视口矩形、参考系变换、关键平台快照、变更原因 |
| `ActorState` | 根位置、参考系、相对速度、朝向、接触集合、运动模式、当前动作与阶段 |
| `MotionIntent` | 停留、沿面移动、起跳、下穿、攀爬、释放接触等受控命令及约束参数 |
| `ActionCandidate` | actionId、目标 ID / 版本、评分项、优先级、最早执行条件、所需接触 |
| `Pose` | 固定顺序骨骼局部角度、躯干局部偏移、头部参数、接触相位；使用可复用数值缓冲 |
| `NormalizedEvent` | 内部事件 ID、时间、类型、来源 ID、Pointer 坐标或数值载荷；不保留原始 DOM Event |

线段用 `P(u) = A + u(B − A)` 表示，`u ∈ [0,1]`。部分可见时保存若干不相交区间；锚点引用原始特征及参数，不能因一次遮挡分段而重新随机编号。

首版自动平台只承诺水平支撑与垂直攀爬边段。即使数据结构能够表示斜线，运动求解器不支持的方向也不能被标记为可站立。

### 3.3 状态与证据分开

| 状态 | 含义 | 对当前人物的处理 |
| --- | --- | --- |
| `valid` | 来源仍有效，当前局部证据和几何可用 | 可进入可达性判断 |
| `offscreen` | 来源可渲染，但在可视视口或祖先裁剪外 | 禁止新目标；滚动离屏时保留锚点并隐藏暂停 |
| `unknown` | 证据不足、预算未完成或复杂遮挡无法判断 | 禁止新动作；优先重测，不把它当可落地的平台 |
| `invalid` | 已删除、不可渲染、身份替换或可用支撑明确消失 | 立即释放接触，转坠落 |

证据为 `explicit-geometry`、`dom-painted-edge`、`text-metric`、`sampled-visibility` 等来源标签和 `strong / approximate / unknown` 等级，不把未经校准的数值包装成真实概率。

当前支撑暂为 `unknown` 时最多维持两个活动帧的待验证状态：停止主动移动，只沿已确认载体变换同步。仍不能验证时隐藏人物并进入 `verification` 暂停，保留最后可靠状态；确认有效后恢复，确认失效后从最后可靠位置坠落。不得在可见画面里无限悬空，也不得把预算不足伪装成已删除。纯背景依赖的当前支撑如果已确定不再满足颜色区分规则，属于 `invalid` 而不是持续 `unknown`。

## 4. 帧调度与时间

### 4.1 活动画面的一帧

1. 合并上一帧以来的事件和失效，处理销毁、暂停和明确删除。
2. **读取阶段**：更新视口及必要参考系；重测当前支撑、接触祖先、当前目标和本步预计碰撞区域。
3. 在剩余扫描预算内发现邻域、细化文字和更新局部可见性；一次提交完成项。
4. 安全仲裁：解除失效支撑、取消过期目标、处理被遮挡/离屏状态。
5. 在需要决策时生成候选并进行可达性判断，不每帧重选随机动作。
6. 用固定步长推进根运动和碰撞。
7. 根据最新根状态采样姿态、融合、解算接触，生成命中几何。
8. **写入阶段**：更新人物宿主 transform 和局部画布；派发合并后的公共状态事件。

模块自身不在写入阶段之后再次读取宿主布局。用户订阅回调若修改 DOM，统一在下一帧重测；不能声称控制了其他脚本或浏览器所有布局工作。

### 4.2 时钟

- 物理步长初值 `1/120 s`；每次 rAF 最多推进 6 个子步。
- 时间戳来自 rAF，禁止用“每帧固定移动 1 像素”。
- 累积时间超过 50 ms 时不进行无限补算；记录迟帧、丢弃过量积压并重新核验几何。
- 根位置可按剩余时间插值，但接触锚点在当前画面几何上重新投影，不能插值到已经失效的平台。
- 页面后台、用户暂停或离屏暂停后清空 accumulator；恢复先重测，再开始下一次时间积分。
- 人物暂未出生或暂停且没有脏事件时，不维持空转的 60 Hz 循环。

### 4.3 预算和优先级初值

这些是待原型验证的调度参数，不是已测得性能。

| 项目 | 初值 |
| --- | --- |
| 动画关键路径 | 桌面 P95 ≤ 2 ms，中端手机 P95 ≤ 4 ms，含同步测量和运动/绘制 |
| 同帧发现/精化追加预算 | 默认 2 ms；移动低功耗档 1 ms |
| 普通自主决策 | 5 Hz；边缘、支撑失效、交互等事件可提前请求一次 |
| 邻域 | 以人物和预测轨迹为中心，初始半径约 400 CSS px，可按速度扩张 |
| 平台缓存 | 最多 1,500 条；当前接触和执行目标先保留 |
| 当前接触/目标 | 首版最多 4 个接触、1 个执行目标 |
| 单次轨迹查询精化对象 | 最多 32 个；超过则降低速度或延后动作，不用旧快照硬跳 |
| IO / RO 观察目标 | 各最多 256 个，优先容器与关键来源，不逐字符观察 |
| 事件队列 | 最多 128 条；Pointer/scroll 合并，安全失效另用集合保存 |
| 低频邻域补查 | 活动时约 500 ms 一次的分片任务，用于补充无事件样式变化 |

时间预算是软预算：一次浏览器几何读取无法被中途抢占。超限需要减少下次工作量和记录原因，不宣称设置 deadline 就能保证耗时。

降级顺序：减少远处发现 → 减少文字精化 → 减少候选数 → 放慢主动探索。不得通过停止当前支撑校验来维持表面 FPS。关键安全区域不能及时确认时，停留或进入验证暂停。

### 4.4 暂停后的恢复调度

暂停主动模拟不等于删除恢复途径。文档可见且没有 `user` 暂停时，`verification`、`offscreen`、`top-layer` 和 `boundary-wait` 保留低频恢复校验：默认每 250 ms 调度一次、最多 1 ms 追加预算，只检查必要来源、参考系、遮挡或入口，不继续全量探索。保留未完成的关键测量游标；同一实例最多一个待执行恢复任务，相关事件可以提前唤醒并合并该任务。

- `valid`：清除对应恢复原因，重新读取关键几何后恢复；其他暂停原因不变。
- `invalid`：立即清除失效接触，移除 verification 原因；没有其他暂停原因时从最后可靠根位置进入 fall。
- `offscreen`：转入或保留 offscreen 原因，不把预算不足误判为删除。
- `unknown`：保持隐藏，下次只续做关键校验，不重启完整扫描。

文档隐藏或存在 `user` 暂停时停止主动恢复计时任务，仅保留必要事件标脏；页面恢复或 `resume()` 后先调度校验。销毁取消恢复任务及游标。这样既不会在后台持续探测，也不会因缺少 DOM mutation 永久卡在验证暂停。

## 5. 页面平台识别

### 5.1 增量发现

输入默认是当前 Document，可配置单个 Element 或可访问 ShadowRoot 为扫描范围。扫描范围不等于覆盖层挂载点。

1. 启动时创建可恢复的遍历游标，只处理当前预算允许的节点；不先同步执行全页 `querySelectorAll('*')`。
2. 可视视口附近以容器和局部命中采样快速建立候选，再逐步补充遍历未命中的可见绘制。
3. `elementsFromPoint()` 仅补充发现，不能遗漏 `pointer-events: none` 的绘制，也不能把透明命中盒视为实体。
4. 不能因为父盒在视口外就裁掉其全部后代：overflow 可见、绝对定位、fixed 子代可能仍在屏幕中。
5. `display: none` 的子树可以跳过；`visibility: hidden` 后代可能显式恢复 visible，不能照搬相同剪枝规则。
6. `display: contents` 无自身平台，继续遍历后代；`content-visibility` 跳过的内容不强行触发大规模离屏布局。
7. open ShadowRoot 单独观察；按 slot 分配遍历实际组合内容，排除未分配、未绘制或重复访问节点。
8. 元素和文本缓存只保留邻域及少量探索窗口。大页面完整发现可以分多轮进行，没有固定“全页全部识别完成”时限承诺。

启动的第一批粗筛完成后即可选择可靠平台。默认首次发现窗口最多使用 250 ms 墙钟时间的分片调度；没有可靠候选就报告 `empty` 并进入受控坠落，后续继续发现。`start()` 不等待全页扫描完成。

### 5.2 绘制证据与平台抽取

#### 边框与纯色块

- 从实际盒片段提取边，不能对多行 inline 一律使用整体外接框。
- 边框要求宽度大于零、样式非 none / hidden、最终可区分；完全透明边框不生成平台。
- 首版 solid 平直边段优先；dashed / dotted 不把空隙填成连续支撑，无法经济地解析实际划线间隔时标为不支持或由 Provider 提供。
- 圆角矩形只保留平直区间；例如顶边去掉左右圆角占据的端部，不能把圆角外接框两角当作地面。
- 纯色块要求在已知底色上可以区分，并尊重 background-clip、边框、padding 等实际绘制范围。
- 元素颜色与底色不可确定时，不凭布局尺寸生成填充平台；明确边框可独立成立。
- 默认文档底色不是平台，避免自动生成覆盖所有内容的整页地板。

#### 背景颜色

先解析可靠 sRGB 纯色与 alpha，在已知背景链上合成，再转 OKLab 计算色差。初始候选阈值 `ΔE_OK ≥ 0.06`、已建立支撑退出阈值 `ΔE_OK < 0.045`，中间区域保留迟滞以减少渐变临界闪烁；这些是工程启发式，必须通过可见性样本校准。

背景链不只是父元素的 background-color：有兄弟叠层、图片、渐变、滤镜或混合模式时真实背景可能未知。无法可靠求得时返回 `unknown`，不默认为白色。不读取跨域图片像素，不把 WCAG 文本对比度当作本项目的物理标准。

opacity 必须考虑祖先合成。接近透明的判定同样是可配置策略，不把 `opacity > 0` 等同于足够可见。

#### 文字

1. 粗阶段从 Text 节点 Range 获得行片段候选，不测量所有字符。
2. 临近人物、即将落脚或进入路径时，才按 `Intl.Segmenter` 细化 grapheme / word。
3. 用文本偏移建立 Range，以实际矩形的垂直位置和视觉横向位置组织平台；不能假定返回顺序就是视觉左右顺序。
4. 空格、换行及指定的 `，。,.` 等标点形成行为间断；名单可配置。
5. 相邻文本节点可在几何连续且没有明确间断时拼接导航关系，但不合并身份；一个词跨不同 span 不应凭空形成大沟。
6. 双向排版按屏幕几何建邻接；纵向 writing-mode 首版不自动生成站立面。
7. 连字或复杂 shaping 造成多个片段重叠时，合并重叠区间并降低细粒度置信度，不声称得到真实逐字轮廓。
8. 不采集 input / textarea 当前值；contenteditable、密码区域和宿主排除区域默认不做文本精化。
9. Range 临时复用，缓存数值矩形及有限偏移，不缓存整页字符串；字体或文本版本变化使相关结果失效。

“文字顶部”明确采用 Range 行片段顶边。人物可能与实际墨迹顶部有字体相关的小间隙，这属于度量近似，不通过隐藏文字或改写布局来掩盖。

#### SVG、图标与其他绘制

- 简单 SVG line / rect 根据实际 fill、stroke、可见性以及 `getScreenCTM()` 转换几何。
- `getBBox()` 仅用于粗筛，不能直接把其顶部作为所有形状的平台。
- stroke-width、linecap、dasharray 和变换必须进入可用区间判断；不支持的复杂边缘不能退回虚假水平 AABB。
- 字体图标按文本处理；图片图标仅以明确外边框或 Provider 几何处理。
- 伪元素、box-shadow、outline、渐变装饰和任意 SVG path 不提供首版通用轮廓承诺；它们可能影响遮挡，无法判断时降级，而非静默忽略后声称精确可见。
- Canvas / WebGL / 视频内部不自动识别；首版示例用宿主维护的数值平台演示 Provider，不截取画面猜测。

### 5.3 裁剪与遮挡

依次处理：来源渲染状态 → 当前可视视口 → 已知 overflow 裁剪链 → 可用边段 → 局部遮挡 → 人物身体空间。

- 对矩形裁剪求交；祖先复杂 clip-path / mask 无可靠适配时，不从完整外框生成平台。
- 沿边段先取端点和中点，再根据遮挡变化细分。初值采样间距不大于 8 CSS px，关键接触附近最多 2 CSS px，并受预算约束。
- 命中测试采样在支撑线上下偏移少量距离，区分平台本体、后代内容和覆盖层；不能只判断最上层是否为同一个 Element。
- 透明的命中盒不是实心遮挡；可见的 `pointer-events: none` 层从已发现绘制中补充判断。
- 层叠上下文无法确定、窄遮挡未采到或复杂透明合成无法解析时，降低证据等级，不宣称像素级正确。
- 支撑线与人物身体胶囊分别检查。能站住脚不表示头部不会被面板遮挡。
- 已知不透明覆盖层挡住人物时，默认隐藏/避让，不依靠高 z-index 把人物画到业务模态之上。

`IntersectionObserver` 用于容器是否靠近视口的提示，`checkVisibility()` 用于辅助排除不可渲染对象；均不能代替上述最终校验。

### 5.4 动态失效来源

| 来源 | 标脏范围 |
| --- | --- |
| childList / characterData | 被移除来源立即失效；被影响文字和布局邻域重测 |
| 属性变化 | class、style、hidden、open 及其他可能参与 CSS 选择器的属性变化，合并到局部或范围级失效 |
| scroll | 对应参考系和裁剪链；固定平台不错误叠加滚动量 |
| ResizeObserver | 观察对象及受影响局部布局；不是所有位置变化的完整通知 |
| pointerover / out、focusin / out、click、toggle | 相关来源和祖先的绘制证据，处理 :hover / :focus / 折叠 |
| transition / animation 事件 | 关键对象在动画期间持续重测，结束后清理 |
| 字体 ready / loadingdone、图片 load、视口 resize | 相关文本和布局区域 |
| Provider 失效通知 | 明确 key，或整个 Provider 作用范围 |
| 低频补查 / 显式 invalidate | CSSOM insertRule、adoptedStyleSheets、无事件 WAAPI 等未被上述覆盖的变化 |

不通过修改 `attachShadow`、样式表方法或绘图 API 来监控整个宿主。新出现的 ShadowRoot 在后续发现或显式 `invalidate()` 时接入。关键当前支撑每活动帧重测，以覆盖缺少事件的 CSS 变化。

MutationObserver 回调只做有界标脏；大量记录折叠为范围级脏标记，不逐条读取布局。自身节点和样式写入通过所有权过滤，避免自触发循环。

## 6. 坐标、锚点与滚动

### 6.1 三种坐标分工

1. **客户区几何坐标**：统一使用当前文档布局视口的 CSS px，接收 DOMRect、Pointer 和局部碰撞查询。
2. **运动参考系坐标**：保存空中人物的根位置与相对速度，支持文档内容、滚动容器内容或视口参考系。
3. **人物局部坐标**：固定骨架与 Canvas 绘制坐标；DPR 只影响像素缓冲，不进入运动单位。

每个参考系提供 `toClient` / `fromClient`。首版内置变换仅接受已验证的二维平移与正向轴对齐缩放；旋转、skew、负缩放、3D / perspective、无法解析的 CSS zoom 不静默套用轴对齐公式。

简单文档参考系：

`client = documentPoint − (scrollX, scrollY)`

简单轴对齐滚动容器内容参考系：

`client = borderBoxClientOrigin + scaledBorderInset + scale × (contentPoint − scrollOffset)`

容器 border box 本身的客户区位置已经包含外层滚动，不能再把所有祖先 scroll 累加一次。组合变换需检查祖先 transform、独立 translate / scale 属性和变换原点；不能只由任意元素的 rect / offsetWidth 粗略推断所有缩放。

`VisualViewport` 的可见矩形在布局视口坐标中为：

`[offsetLeft, offsetTop, offsetLeft + width, offsetTop + height]`

未提供 VisualViewport 时采用布局视口矩形。手机缩放时不随意再乘 `scale` 到 CSS 几何；默认人物随页面一起缩放，不另做屏幕物理尺寸恒定策略。

### 6.2 有支撑时

保存原始平台特征上的参数 `u`。当前接触点为：

`contactClient = A(t) + u × (B(t) − A(t))`

- 站立时 `u` 保持；主动沿平台行走时才根据相对路程改变。
- 归一化锚点会随平台伸缩保持相对比例；平台变小导致支撑不足时解除接触，不强行压缩人物。
- 支撑脚、手、臀分别锁定必要接触；根位置由接触和姿态约束计算。
- 平台 DOMRect 已经变化时，不再额外给接触点加 scroll delta。
- 文字 reflow 后先依据来源代次和偏移重新识别特征。无法唯一对应时释放旧锚点，不跳到另一行同名文字。
- fixed / sticky 在接触期间都采用当前实际几何，不依靠 CSS position 字符串推断位置。

### 6.3 离开支撑与空中运动

起跳或释放接触时，转换当前唯一根参考点，而不是把某只脚、手或臀部接触点当作根；保留客户区位置连续性：

`rootLocal = fromClient(previousRootClient)`

各接触点由根位置、当前姿态和对应局部偏移关联。解除接触不重定义根的含义；接触点用于约束和求起跳条件，不能直接替换根坐标。

参考系规则：

- 普通文档平台使用文档内容参考系。
- 嵌套滚动平台使用最近的有效滚动内容参考系。
- 真正以布局视口为包含块的 fixed 平台使用视口参考系。
- transformed ancestor 内的 fixed 不是上述视口 fixed，按其已验证参考系处理。
- sticky 起跳后默认进入最近滚动内容参考系，不再随原平台继续吸顶；接触期间仍按实际 sticky 几何定位。

空中根轨迹在该参考系积分，每帧投影到客户区与新平台比较。离开平台后不继续追踪平台自身的 CSS 平移动画；可以继承起跳前测得、去掉参考系滚动后的平台速度，继承值必须限幅。

页面滚动是参考系变化，不是物理冲量，也不计入步态距离。参考系节点被删除时，将最后可靠客户区位置重基到文档参考系，保留合理速度；无法确定变换时先验证暂停，不使用 NaN 或旧节点矩阵继续模拟。

### 6.4 离屏规则

先判断参考系/视口变化，再判断本步主动运动是否越界：

1. 若保持上一步人物局部状态，仅更新滚动/视口就导致离屏，则属于被动离屏。
2. 被动离屏隐藏人物，暂停主动动作和积分，保留锚点或空中状态；保留必要事件唤醒和有限来源引用。
3. 来源明确隐藏或移除不是单纯离屏，仍标记支撑失效；恢复可见时不得复用无效锚点。
4. 折叠使祖先高度/裁剪区域收缩、最终消除当前支撑区间时，属于支撑失效；仅 scrollOffset 或可视视口改变造成的裁剪才按被动离屏处理。根据失效来源和前后几何区分，不能只用“在裁剪框外”一个布尔值。
5. 重新进入视口时重测平台、身体空间和参考系，然后恢复时间积分。
6. 人物因自身运动主动越界才进入第 8 节边界循环。
7. 出生和循环的主动入场带有 `entering` 标记，不因最初位于边界外就立即触发离屏暂停；沿有限入口走廊继续积分，进入画面后清除标记。入口被阻挡或入场超过 2 秒模拟时间仍未完成时，隐藏并等待重新验证，不进行无限重生。

这是一项推荐产品取舍：优先保持相对位置，不保证滚动过程中始终能看见人物。用户若需要“永远可见”，应另行确认重生策略，不能同时声称无条件保留原锚点。

## 7. 行为选择与运动

### 7.1 两层状态

运动模式只有 `supported`、`airborne`、`climbing`、`suspended`；动作是模式内部的运行实例，例如 walk、sit、jump。

安全层优先决定模式，再由行为层决定动作。Provider 或触发器可以请求动作，但不能自行把无支撑人物设置为 supported。

普通行为候选：

`score = 基础权重 + 新颖性 + 目标吸引力 − 重复惩罚 − 动作成本 − 不确定性惩罚`

只在满足进入条件的候选之间进行有种子加权随机。维护短小的最近动作/平台环形记录，避免在两个按钮间无限机械往返；不维护全页长期行为档案。冷却按模拟时间计算，后台停留不一次性触发大量超时行为。

### 7.2 可达性与局部导航

首版默认短程滚动规划，不预建全页全连接图。

- 从当前平台、边缘及预测方向查询局部索引。
- 先判断站立宽度、垂直差、距离、接触和运动能力，再计算轨迹。
- 优先直接移动或单次跳跃；必要时做有界的 2—3 次动作前瞻，执行前每次重新校验。
- 候选上限初值 12，路线扩展上限 64；超限选择可行短程动作或停留，不执行未完成路径。
- 路线绑定来源代次及几何版本；目标移动可重新计算未起跳轨迹，已经起跳不得瞬间修改根位置追踪目标。
- 没有可达目标时允许 idle、turn、look-around 或安全坠落，不能“智能”瞬移。

### 7.3 走跑和边缘预判

以人物高度 `H` 归一化运动参数，建议初值：走速 `1.5H/s`，跑速 `4H/s`，最大水平加速度 `12H/s²`，重力 `18H/s²`，最大坠落速度 `12H/s`。实际表现由原型调整。

边缘安全距离至少包含制动距离和当前测量余量：

`dStop = v² / (2a) + safetyMargin`

前方出现文字间断或平台端点时，先制动/确定起跳点再执行动作。若本帧预算未完成前方精化，应降低速度，不能高速冲向未知区域。

### 7.4 跳跃

设屏幕向下为正，重力 `g > 0`：

`x(t) = x0 + vx × t`

`y(t) = y0 + vy0 × t + 0.5 × g × t²`

在起跳速度、最高跃起高度、可用助跑距离和落脚区间约束内求下降阶段的相交时间。区分 hop、普通 jump、standing-long-jump 和 running-long-jump 的起跳能力与前置条件；不能只用四个名字调用同一无约束抛物线。

移动目标使用短期速度预测来提高候选质量，但不承诺任意加速目标必定落中。轨迹进行局部可见障碍检查；下落途中更早遇到有效平台时在实际接触处落地，不穿过它去追原目标。

根位置连续；落地竖直速度归零或限幅属于物理接触变化。身体压缩由姿态处理，不能继续把脚画到平台下方。

### 7.5 碰撞和单向平台

平台默认是一向支撑面，不是整个 DOM 矩形实体：上升可穿过支撑线，下降从上方跨过时才接触。攀爬边仅提供接触能力，不自动形成阻挡全场的墙。

使用上一时刻到当前时刻的相对运动扫掠：比较人物脚点/支撑胶囊与平台上一、当前几何，求最早有效接触时间。脚部水平投影必须落在可用区间内，法向相对速度必须朝向支撑。精化失败或复杂剧烈形变时，取消目标/验证暂停，不以旧矩形“补落地”。

`drop-through` 只登记原 SurfaceId 的临时忽略令牌：脚离开原支撑带且向下通过后释放；另设有限安全超时，不能永久屏蔽该平台。其他下方平台照常参与碰撞。

### 7.6 攀爬、坐姿与动作结束

- climb-up / down 需要有效垂直边段、手脚可达接触和顶部/底部可站立区间。
- ledge-grab 只在手臂可达范围内建立手部接触；pull-up 必须先验证头部、躯干和落脚空间。
- 坐姿需要臀部支撑和腿部空间；狭窄文本片段不能一概允许坐下。
- 无可用后续支撑的动作结束后根据实际接触选择 supported 或 airborne，而不是无条件切回 idle。
- 所有动作被删除平台打断时清理原接触请求，再进入 fall。

## 8. 边界循环

以当前可视视口为循环边界，基于人物动作包络而不是根点单独判断。首版 `wrapX` 控制左右互通，`wrapY` 仅控制坠落后下出上入，不实现向上越界后传送到底部。

- 自身运动使人物完整越过右边界后，在左边界外的对应高度重新进入；左侧对称处理。
- 自身坠落完整越过下边界后，从上边界外相同横向位置继续下落。
- 起跳暂时完整越过上边界时，保持 airborne 和原参考系，继续受限积分直到自然回落；只裁掉画面外的绘制，不添加 offscreen 暂停或循环。该状态不同于页面滚动造成的被动离屏，用户/后台暂停仍然生效。
- 保留限幅后的速度和朝向，清除接触、原执行目标、旧路线、下穿令牌和不兼容动作阶段。
- 重新进入位置若有已知遮挡，先隐藏并有限搜索空闲入口；无可用入口时暂停等待场景变化，不无限瞬移循环。
- 同一物理步最多处理一次循环；横纵同时越界按本步最早穿越边界处理，下一步再判断另一轴。
- wrapX / wrapY 关闭时，不建立虚构地面。横向优先在边缘制动/转向；已离开画面或纵向跌出时隐藏并进入边界等待，直到显式重新定位或可见条件改变。

滚动、软键盘、窗口 resize 和 pinch zoom 只改变可见范围，不触发人物主动循环。

## 9. 骨架、姿态和渲染

### 9.1 固定拓扑

骨架包含 pelvis、chest、neck、head，以及左右 shoulder / elbow / wrist、hip / knee / ankle 接点。骨段比例相对标称高度 H 定义，角度是局部弧度，方向通过求解统一映射。

circle / square 只改变头型绘制。线宽、颜色、骨段比例属于外观配置；任意新增肢体或拓扑不承诺复用标准动作，需要后续骨架映射方案。

根是固定的运动参考点：以标准直立姿态下双脚支撑中心为其局部原点定义，不随着某只脚、手或臀部成为支撑而重新定义，也不等同于 pelvis 的绘制位置。坐下、落地压缩等通过局部躯干偏移和接触约束实现，不能暗中向世界坐标添加一段第二套动画位移。

### 9.2 姿态求解顺序

1. 根据动作阶段、相对速度、接触相位和动作局部时间采样姿态。
2. 从当前已经显示的姿态开始融合，角度采用最短角差。
3. FK 生成关节位置。
4. 对当前必须保持的脚、手或臀接触进行 IK / 根局部偏移修正。
5. 限制关节范围、检查骨长和接触可达性。
6. 输出绘制姿态与下一帧融合起点。

普通融合时间初值 80—180 ms，具体动作配置；安全中断可以立即换运动模式，但保留尽可能连续的肢体姿态。不能用全局固定 crossfade 时长处理所有动作。

走跑步态以相对平台路程推进：`phase += distance / strideLength`。支撑期脚锁定锚点，摆动期用弧线抬脚。切换 walk / run 时匹配支撑脚和相位，不从 phase = 0 开始。

站立转向保留支撑脚，通过转身姿态再交换朝向；不能直接镜像带来双脚瞬时换位。IK 超出骨段可达范围时缩小局部偏移、释放可释放接触或取消动作，不拉长腿。

### 9.3 24 个动作的实现要求

| 动作 | 主要进入条件 | 运动/接触特征 | 退出或中断 |
| --- | --- | --- | --- |
| idle | 稳定支撑 | 零主动速度，小幅或静止姿态 | 决策/交互；失效立即打断 |
| walk | 有可行走区间 | 低速距离驱动步态 | 制动、转向、跳跃 |
| run | 足够区间和加速空间 | 高速步态与身体前倾 | 提前制动或助跑起跳 |
| brake | 有支撑且仍有速度 | 限减速度，保持接触 | 速度达到目标后结束 |
| turn | 转向空间足够 | 保留支撑脚，受控方向转换 | 新朝向稳定 |
| step-over | 小间断可单步覆盖 | 抬腿跨越，必要时短暂单脚支撑 | 接触另一片段 |
| hop | 小水平/垂直差 | 低幅双脚或单脚轻跳 | 下降接触 |
| jump | 目标满足一般起跳能力 | 标准受限抛物线 | 落地、失去目标后继续物理下落 |
| standing-long-jump | 站立、目标在立定能力内 | 蓄力姿态后起跳，无伪造助跑 | 下降接触 |
| running-long-jump | 有足够助跑距离与速度 | 速度连续接入远跳 | 下降接触 |
| drop-through | 下方存在可行候选或允许坠落 | 临时忽略当前支撑 | 穿过原支撑带后释放令牌 |
| fall | 无有效接触 | 重力、终端速度、下落姿态 | 落地/边界 |
| land-soft | 较小相对落地速度 | 脚接触，短压缩 | 稳定后 idle / walk |
| land-hard | 较大相对落地速度 | 更明显压缩与恢复，不穿平台 | 恢复或支撑失效 |
| climb-up | 可靠竖边和上方落点 | 交替手脚接触，限速上移 | pull-up / 安全释放 |
| climb-down | 可靠竖边和下方空间 | 交替下降接触 | 下方支撑/释放 |
| ledge-grab | 手可达边缘 | 手锁定边缘，根悬挂 | pull-up / drop |
| pull-up | 已抓边且上部空间可用 | 手到脚接触的受控交接 | 上方稳定支撑 |
| crouch | 脚部稳定且有下蹲空间 | 降低躯干，不改变世界脚点 | stand-up / jump |
| sit | 臀部支撑及腿部空间可用 | 臀锚点、腿部姿态 | stand-up；失效即 fall |
| stand-up | 坐/蹲且头部空间足够 | 从实际姿态恢复到脚部支撑 | 稳定后下一动作 |
| wave | 支撑允许释放一只手 | 单臂反馈，不改根轨迹 | 完成或高优先事件 |
| look-around | 稳定支撑 | 头/躯干观察姿态 | 完成或移动 |
| recoil | 交互且退让空间可行 | 原地惊讶或受限小退步 | 回稳；不无条件后退坠落 |

### 9.4 Canvas 层

- 默认一个实例对应一个小 Canvas，透明背景，宿主 `position: fixed`、`pointer-events: none`、`aria-hidden=true`。
- 按动作声明的最大局部包络计算画布，外观变化或新动作需要更大包络时才重新分配。
- `effectiveDpr = min(devicePixelRatio, configuredMaxDpr)`，默认上限 2；更改浏览器缩放/显示器时按需更新。
- CSS px 保留浮点精度，避免每帧取整导致慢速运动抖动；像素对齐只用于适合的绘制细节。
- 避免阴影模糊、全屏清除、逐帧分配 Path2D / 大数组或反复修改 canvas 尺寸。
- 仅更新自身 transform，不每帧修改 top / left 导致布局链；不默认全局添加 will-change。
- 渲染器边界内部保留，但首版只发布实际实现的 Canvas 渲染器，不提供空的 SVG / WebGL 模式选项。

### 9.5 挂载、top layer 与 CSP

默认宿主附加到所属文档的合适顶层位置，并校验 fixed 包含块。宿主提供自定义 mount 时，必须使用其坐标映射，不把任意挂载点当作视口原点。

Shadow DOM 可用于隔离人物样式，但不把它宣传为安全边界；宿主样式、继承、CSP 和挂载变换仍需测试。只设置自身节点必要属性，不修改 documentElement / body 的全局样式。

- 普通遮挡：局部避让或隐藏。
- 模态 dialog：默认暂停/隐藏，不抢焦点、不为了人物调用 showModal。
- fullscreen：默认避让；要在 fullscreen 内运行，由宿主明确提供内部挂载点。
- popover：正常尊重其可见遮挡与层级，不靠最大 z-index 越过。
- 无法访问的 closed root 内特殊层：通过宿主集成明确通知，不承诺自动识别一切。

样式注入提供 `styleNonce`；禁止依赖 eval、内联事件处理器、blob Worker 或全局样式覆盖。严格 CSP 环境若不允许运行时样式，应由宿主加载包的静态基础样式并按已验证策略挂载；这项兼容必须实际测试，不能仅凭提供 nonce 宣称通过。

## 10. 交互与触发仲裁

### 10.1 输入获取

在扫描根所在文档及需要的可访问 ShadowRoot 上注册有限的事件代理。以 composedPath 关联来源，重复路径按原始事件去重。

- pointermove 只保留最新坐标，每帧最多进行一次人物/邻域几何距离计算。
- 人物命中使用头部形状和骨段胶囊，命中宽度可略大于线宽；不创建遮挡页面的透明点击层。
- click 同时命中人物与宿主按钮时，两者事件事实均记录，但一次仲裁只启动一个兼容动作。
- 键盘触发的 click 不因默认 clientX/clientY 为零而误判点击人物，应依据输入来源和来源元素处理为 host-click。
- 不调用 preventDefault / stopPropagation，不合成宿主点击，也不读取输入值。
- hover 进入/离开与人物靠近使用不同距离阈值，避免边界反复触发。

### 10.2 优先级

从高到低：销毁/暂停 → 明确支撑失效 → 碰撞/边界 → 人物直接交互 → 所在元素交互 → 路线动作 → 普通随机活动。

安全事件是内部规则，20 类标准触发中的相应事件仅提供观察和兼容动作选择，不能覆盖安全结果。普通触发有 priority、cooldown 和 guard；高优先级不意味着能够突破物理能力。

扩展回调抛错时隔离该扩展、释放其资源并发出一次有界错误事件，不在每帧重复调用失败插件。同步回调无法被强制中止，耗时插件会影响宿主；预算仅检测并在后续禁用，不能假装具有线程沙箱。

## 11. 公共 API 与扩展契约

以下是接口设计，不是可直接运行的实现。公共名称在批准后的第一阶段固定，接口修改须同步需求与示例。

### 11.1 创建配置

| 字段 | 类型/默认值 | 说明 |
| --- | --- | --- |
| `root` | Document / Element / ShadowRoot，可省略 | 在 start 时解析；限制扫描范围，不自动改变挂载点 |
| `mount` | HTMLElement，可省略 | 可选人物层挂载点，需通过坐标/可见性校验 |
| `seed` | number，可省略 | 可复现随机序列；不保证跨浏览器不同字体布局仍完全一致 |
| `appearance.height` | number，32 | CSS px 标称高度 |
| `appearance.color` | string，默认深色 | 解析为允许的 Canvas 颜色，不拼接 HTML |
| `appearance.lineWidth` | number，暂定 2 | 正数，随外观校验 |
| `appearance.head` | circle / square，circle | 固定拓扑下头型 |
| `appearance.proportions` | 骨段比例表，可省略 | 受限正值，重算包络与接触 |
| `boundary.wrapX / wrapY` | boolean，均 true | wrapX 左右互通；wrapY 下出上入，向上起跳越界自然回落 |
| `recognition.exclude` | Element 集合或谓词 | 排除平台与文本精化；回调属于宿主性能责任 |
| `recognition.punctuation` | 字符集合，包含中英文逗号句号 | 文字行为间断规则 |
| `recognition.colorThresholds` | enter / leave | 颜色证据迟滞阈值 |
| `performance.scanBudgetMs` | number，2 | 新发现/精化追加预算 |
| `performance.maxSurfaces` | integer，1,500 | 有界缓存 |
| `performance.maxDpr` | number，2 | 缓冲缩放上限 |
| `motionPreference` | respect / full，respect | 默认尊重 prefers-reduced-motion |
| `styleNonce` | string，可省略 | 仅用于自身样式资源的 CSP 集成 |
| `debug` | boolean，false | 启用有界数值诊断 |

create 仅保存配置并构造纯数据，不读取全局 document、测量页面或调用插件。参数在公共入口校验，内部数值管线依赖已校验契约。

### 11.2 实例方法

| 方法 | 返回与行为 |
| --- | --- |
| `createStickFigure(options?)` | 返回独立实例；默认入口安装标准动作/触发，core 入口只安装安全运行所需基础能力 |
| `start()` | Promise<StartResult>；创建资源并完成第一批发现，结果为 ready / empty / paused，附能力报告；重复调用复用当前启动任务 |
| `pause()` | 增加 user 暂停原因，隐藏人物并停止主动模拟；保留必要恢复状态 |
| `resume()` | 仅清除 user 原因，排队重测；其他暂停原因仍生效 |
| `destroy()` | 幂等释放全部实例资源；进行中的 start 被取消，之后 start 拒绝并给出 destroyed 错误 |
| `setAppearance(patch)` | 下一帧原子应用外观，重算包络和能力；不允许负骨长/非法高度 |
| `invalidate(target?)` | target 为来源节点或省略的全范围标脏；不立即执行无界同步扫描 |
| `place(target)` | Promise<PlaceResult>；target 为来源元素或 SurfaceId 与参数 u，局部验证后定位；不可站立返回原因，不绕过验证 |
| `requestAction(actionId, options?)` | Promise<ActionResult>；经过相同 guard 与能力校验，返回 completed / rejected / interrupted 及原因 |
| `on(event, listener)` | 返回 disposer；订阅 ready、actionchange、surfacechange、boundary、statechange、error、diagnostic |
| `emitCustom(name, payload?)` | name 必须为 custom:*；只投递扩展事件，不能伪造删除/碰撞事件 |
| `registerClip / registerAction / registerTrigger / registerSurfaceProvider` | 返回 disposer；同一实例同类 ID 重复注册拒绝，不覆盖已有定义 |
| `getSnapshot()` | 返回只读值快照，无 DOM 引用和原始文本；调试用途，不每帧创建大对象 |

`place` 用于演示定位、测试和宿主显式控制，定位本身是请求的瞬时变化；自动行为不得用 place 实现跳跃。运行中变更 root / mount 不在首版 setOptions 范围，需销毁后创建新实例，避免隐藏的跨文档迁移。

### 11.3 动作与触发扩展

| 扩展 | 必须提供 | 运行约束 |
| --- | --- | --- |
| `AnimationClip` | id、骨架契约版本、最大局部包络、sample(context, outputPose)、完成/接触相位定义 | 纯数值采样，不访问 DOM、不自行推进世界位置、不每帧分配大量对象 |
| `ActionDefinition` | id、所需 clips、canEnter、创建运行实例、step / exit | 输出受控 MotionIntent 和姿态选择；动作状态属于每次运行，不存共享全局单例 |
| `TriggerDefinition` | id、订阅事件、priority、cooldown、evaluate | 返回候选或空，不直接启动动画或改 ActorState |

动作可以组合现有运动原语，不需要改核心状态机。需要新增根运动原语或骨架拓扑时，属于新的能力需求，而不是让任意插件写入根位置。

注销时先停止相关运行实例、解除依赖和资源，再移除定义；正在空中的人物继续受 fall 安全能力管理。基础安全能力不能通过普通 disposer 注销。Clip 被已注册 Action 依赖时，拒绝单独卸载并说明依赖，或由调用方按依赖顺序卸载，不静默留下悬空引用。

注册自定义动作的标准流程：新增独立算法文件 → 显式 import → 注册 clip / action / trigger → 验证动作可达性与销毁。内置预置以同一接口组装，但安全规则位于内核而非可覆盖插件。

### 11.4 SurfaceProvider

Provider 面向 Canvas 内部平台、closed Shadow DOM 协作、虚拟列表身份以及复杂绘制。首版必须实现并测试完整注册/失效/卸载路径，而非只有接口声明。

| 方法/字段 | 契约 |
| --- | --- |
| `id` | 实例内唯一 Provider ID |
| `connect(context)` | 获取 AbortSignal 和 invalidate(keys?)；返回清理函数，不自动联网 |
| `collect(request)` | 同步、可分片的候选发现；输入客户区 region、预算和扫描 token，返回候选及是否完成 |
| `measure(keys, frame)` | 针对已知关键 key 的直接测量，返回 valid / offscreen / unknown / invalid 与最新几何，不能要求先全量扫描 |
| `dispose()` | 释放订阅、宿主引用和游标；与 connect 清理幂等协作 |

每个候选包含稳定 key、sourceRevision、宿主 owner（可选）、参考系、几何线段、支持能力、裁剪区间、绘制有效性和几何版本。参考系使用 `viewport`、`document` 或已注册滚动内容参考系；不混用物理像素和 CSS px。

- 有 owner 时核心再检查其祖先可见性和裁剪；内部轮廓真实性由 Provider 负责。
- 无 owner 的虚拟平台必须显式提供可见性、裁剪和失效生命周期，不能靠永久 valid 蒙混所有检查。
- collect 的扫描 token 固定 Provider、查询覆盖区域、过滤条件及扫描代次；分片结果只增加/更新当前返回项，未返回的项不立刻删除。滚动导致 region 改变时启动新查询，不把两次局部扫描当作同一全量快照。
- 完整扫描只允许在该次明确覆盖范围内淘汰非关键探索缓存；区域外平台不受“本轮未出现”影响。缓存淘汰不等于来源已失效，后续仍可重新发现。
- 当前锚点和执行目标不因未出现在 collect 结果中而删除，必须通过关键 measure、来源代次变化或明确的 remove 通知确定失效。Provider 的显式删除与 measure invalid 立即生效，不等待扫描结束。
- collect / measure 在主线程执行，其同步耗时不可抢占；外部耗时计算应自行异步准备只读结果，再通知失效，不能让主帧 await。
- Provider 注销时其所有平台立即失效；当前人物正常释放接触。

### 11.5 错误与回调

公共配置错误、重复 ID、失效引用和不支持挂载给出稳定错误代码与简短原因。扩展失败用 error 事件隔离；没有可靠恢复条件时停止该扩展，而不是无限重试。

公共事件在当前写入完成后批量派发。回调中的注册、注销、外观变化与动作请求排入下一次安全边界；destroy 立即标记销毁并阻止后续回调，实际资源清理必须幂等。

## 12. 生命周期、可访问性与资源

生命周期为 `created → starting → running / paused → destroyed`。暂停原因为集合：`user`、`document-hidden`、`offscreen`、`verification`、`top-layer`、`boundary-wait`。running / paused 是结果，不把各种原因互相覆盖。

`prefers-reduced-motion` 是动作策略，不自动覆盖用户 pause：默认停止随机行走/跳跃，只提供稳定姿态和简短、低运动反馈；如果支撑失效，先隐藏并重新寻找稳定位置，不强制播放长距离坠落和循环。宿主显式选择 full 才恢复完整装饰性运动。

资源清理清单：rAF、延迟任务、document / root / visualViewport 监听器、MO / IO / RO、媒体查询监听、字体和图片订阅、所有插件 disposer、装饰节点、Canvas 缓冲、源表强引用、缓存 Range、事件订阅和未完成请求。

- DOM 来源与弱引用映射分开，不能因为使用 WeakMap 就假定所有缓存都不会泄漏。
- 页面隐藏时不靠高频 setInterval 保持后台识别。
- 主动离屏缓存保留当前接触必要来源，不保留完整离屏子树索引；删除通知要及时释放。
- 首版每个实例管理一个人物，标准性能验收使用一个活动实例；多人物共享世界不在首版范围。
- 不使用模块级可变单例共享动作、随机数或场景状态。宿主额外创建实例时，各自资源必须独立释放，但多个活动实例不属于单人物性能预算保证。
- 在同源 iframe 内独立安装实例属于另一个 Document，不构成跨文档共享世界。

## 13. npm 与技术栈接入

### 13.1 发布结构

拟发布 `mono-stickfigure`，名称及许可证待发布前确认。

- 默认入口：安全内核、DOM 识别、Canvas 渲染和标准预置。
- `/core`：不自动安装完整标准行为的基础组合入口，保留坠落/碰撞/生命周期必需能力。
- `/presets`：实际标准预置的显式导出，用于选择性组合。
- CSS 资源仅在实际采用静态基础样式时发布对应文件和明确入口。
- 不导出 `/worker`、`/vision`、`/react` 等未实现入口。

ESM / CJS 由同一源码构建，采用明确的 package type 和 import / require 条件 exports。声明按模块模式正确配对，例如 ESM 的 `.d.mts` 与 CJS 的 `.d.cts`，不能仅有“文件存在”但 TypeScript 无法解析。

浏览器 ESM 产物可通过相对 URL 或 import map 使用；CJS 是兼容构建工具/Node import 的格式，不表示浏览器会直接执行 require。导入不访问 DOM、不开线程、不注册全局副作用；tree shaking 的 sideEffects 声明必须与真实 CSS 资源和入口行为一致。

发布白名单只包括实际 dist、类型、必要许可证与使用说明；`npm pack` 后从 tarball 安装到独立消费夹具测试，不只从源码 alias 测试。

### 13.2 框架接入

| 环境 | 接入规则 |
| --- | --- |
| 原生 HTML / JS | 页面可用后 create / start，业务卸载时 destroy |
| React | 客户端挂载后启动，effect 清理中销毁；开发期重复挂载不得泄漏；不每帧 setState |
| Vue / Svelte | 组件挂载/卸载管理实例，布局批量更新后可 invalidate |
| SSR 框架 | 服务端允许安全 import；start 仅客户端执行，必要时动态导入 |
| Electron / WebView | 按实际内核、CSP 和宿主窗口生命周期测试，不默认开 Node 权限 |
| Shadow DOM 组件 | open 自动纳入；closed 由组件提供 root / Provider |
| iframe | 默认只识别可靠外边框；内部独立实例由宿主自行接入，跨 frame 运动后续实现 |

首版提供接入示例与生命周期验证，不引入 React / Vue 为核心运行时依赖，也不发布未测试包装包。

## 14. 后续线程与视觉扩展边界

### 14.1 Worker

只有实测局部数值规划成为瓶颈时才引入 Worker，不将首版简单算法预先拆成消息系统。

后续消息必须包含协议版本、requestId、sceneVersion、参考系版本和 actorEpoch；主体仅为数值快照。最多一个在途请求和一个最新待处理请求，合并过期工作，不能建立无限消息队列。

返回结果只能作为候选，主线程核验目标来源代次、参考系及当前位置后接受。销毁、重新定位、支撑失效和循环都会改变 actorEpoch，使旧结果无效。转移 ArrayBuffer 后发送方不可继续访问原缓冲；有明确池化/归还协议再使用 transfer，不默认 SharedArrayBuffer。

Worker URL 和 CSP 由宿主明确集成；默认不创建 blob URL 绕过策略。OffscreenCanvas 与 Worker 路线规划是不同优化，需要分别测量收益。

### 14.2 截图 / 大模型

首版不实现远程识别、不选择模型、不保存密钥，也不把外部模型塞进实时物理循环。

未来若用户单独要求：宿主提供经授权和脱敏的截图 → 附上裁剪矩形、CSS/像素映射、视口及场景版本 → 服务端或本地视觉处理 → 输出候选线段 → 核心重新验证并通过 Provider 接入。

- 浏览器无通用无权限真实合成截图接口；不能用 DOM 重绘库冒充无损截图。
- 跨域 Canvas 污染、授权、隐私、网络延迟、图像缩放和稳定身份必须单独处理。
- 只把图像当数据，不执行截图文字中的指令或返回的脚本。
- 过期截图结果丢弃，低置信候选不直接成为当前支撑。
- 失败或超时不影响纯 DOM 模式，不自动上传更多页面试错。

## 15. 五个场景的端到端流程

| 场景 | 识别 → 决策 → 运动 → 验证 |
| --- | --- |
| SC-01 文字 | 邻域 Range 分片 → 发现空格/指定标点 → 查询跨越能力 → step-over / hop / jump → 脚部接触下一片段并按路程继续跑 |
| SC-02 按钮 | 边框/填充证据 → 两按钮落脚区间与间距 → 检查助跑和抛物线 → 立定或助跑远跳 → 实际下降碰撞决定落地；不可达不硬跳 |
| SC-03 表格 | 单元格边段及裁剪 → 选择下方可用区间 → 给当前边段下穿令牌 → 下落扫掠 → 首个有效下方接触，释放令牌 |
| SC-04 面板 | 面板平台当前有效 → 隐藏/移除或绘制消失 → 安全层释放脚/臀接触 → 从最后位置 fall → 下方落地或主动越过底边后 wrap |
| SC-05 树 | 子节点来源及祖先链 → 父节点折叠引起渲染/裁剪失效 → 不依赖子节点 isConnected 单值 → 释放接触 → 自然下落，不瞬移到折叠后的目录位置 |

每条流程必须由真实 DOM 状态驱动。测试可以固定初始位置、种子和动作请求，但不能把预先写死的平台坐标作为自动识别已经通过的证据。

## 16. 设计确认与实施闸门

本设计继续沿用调研文档的待确认事项，并增加以下需要原型验证的技术闸门：

1. 当前支撑的逐帧测量、文字精化与普通帧预算是否能够同时达标。
2. Canvas / SVG 小型对比是否支持保留默认 Canvas 决策。
3. 嵌套滚动、sticky 起跳、移动视口和 transformed mount 是否满足坐标误差门槛。
4. 24 个动作是否在小尺寸下有清晰差异，IK 与融合是否能达到无明显脚滑。
5. 基础自动识别对未知绘制的保守策略是否具有足够平台覆盖率。

这些闸门在用户批准文档后通过本地原型与测试验证。发现冲突时先给出数据和取舍再修订基线，不静默减少五个场景或绕过宿主安全边界。
