## 1. 产品目标

开发一个可以附加到现有 Web 页面上的 npm 工具包。在不改变页面业务结构、不阻断交互的前提下，让一个小型火柴人在当前可见且可达的页面平台上自然活动。

核心体验包含：自动寻找平台、随机但合理的行为、连续可中断的动作、元素移动与滚动时保持相对位置、平台消失时自然坠落，以及人物和宿主交互后的反馈。

首版必须完整实现五个原始示例，不以“固定测试坐标上的人物动画”作为完成标准。

2026-11-14 预览版已实现边框、fill、文字顶部、16 个可请求动作和有界目标导航；本节以下的 Provider、简单 SVG、组合树遍历、24 动作/20 触发等仍为完整首版目标。实际接口见 [README.zh.md](../README.zh.md) 与详细设计第 11 节，阶段验证见实施与验收计划第 13 节。

## 2. 术语与边界

| 术语 | 本项目定义 |
| --- | --- |
| 元素 | DOM 元素、文本片段，以及由宿主适配器提供的虚拟绘制对象 |
| 可见 | 在当前可视视口及已知裁剪区域内，有可靠绘制证据，未被已知遮挡完全覆盖 |
| 平台 / Surface | 可以建立脚、手或臀部接触的线段；不是任何布局盒的顶边 |
| 可站立 | 支撑区间长度、局部可见性和人物身体空间满足动作要求 |
| 可达 | 在当前速度、重力、跳跃和攀爬约束下能够到达，而非仅出现在候选列表 |
| 锚点 | 人物在平台某个稳定几何特征上的相对接触位置 |
| 运动参考系 | 空中轨迹或平台运动所属的文档、滚动容器或视口坐标空间 |
| 动作定义 | 行为进入条件、运动意图和姿态片段的组合 |
| 动画片段 | 输出骨架姿态的算法或关键姿态数据，不直接改写世界位置 |
| 适配器 | 提供无法由普通 DOM 自动获得的几何、身份或失效通知的可选模块 |

### 2.1 不可省略的限制

- 普通文字采用 Range 与字墨度量的顶部近似；大号水平 ltr 文字采用本地字体重绘的顶部轮廓近似，两者都不是页面逐像素识别。
- 可见性采用有限局部校验，不能保证识别所有窄遮挡和复杂绘制。
- 默认自动识别面向水平排版、常见轴对齐 DOM 平台和简单 SVG；复杂旋转、3D、任意 mask / clip-path 不从外接框猜平台。
- closed Shadow DOM 与跨域 iframe 内部需要宿主主动协作，不能绕过浏览器安全策略。
- Canvas、WebGL、视频和图片内部的平台需要几何适配器；明确外边框可作为独立平台。
- 不保证人物在有限时间内访问所有可见元素，也不保证无法物理到达的平台被自动访问。
- 任意原生网页技术栈不等于原生非 Web UI。React Native 原生视图、原生桌面控件、没有 DOM 的小程序渲染层不在直接支持范围内。

## 3. 首版功能需求

所有标记为“必须”的功能均属于完整首版，实施阶段中的先后顺序不构成范围削减。

### FR-01 初始化与随机出现（必须）

1. 通过显式 API 创建并启动实例，不在 import 时创建节点或开始动画。
2. 默认启动一个人物，在当前可见、可站立平台中随机选择初始位置。
3. 候选必须满足人物身体空间和最小支撑长度要求。
4. 无有效平台时可从当前可视区域上方进入坠落；不凭空创建透明容器地面。
5. 支持测试和演示指定初始目标元素；这不改变默认随机行为。
6. 提供随机种子用于同一场景输入下的可复现测试。

### FR-02 自动平台识别（必须）

1. 识别具有可见绘制证据的平直边框、可区分纯色填充块、文字片段顶部、简单 SVG 线段和矩形边段。
2. 区分布局容器与真实绘制实体；透明无边框容器不能仅凭矩形生成平台。
3. 考虑视口、滚动容器裁剪、祖先渲染状态和已知局部遮挡。
4. 平台可被部分遮挡时，拆分可用区间，而不是仅用元素整体可见标记。
5. 识别当前 hover / focus 状态产生的临时平台，状态撤销后重新判断。
6. `display: contents` 等没有自身盒子的节点不作为平台，但仍处理可见后代。
7. 默认排除工具包自身覆盖层；支持宿主配置排除根或元素。
8. 首版自动处理 open Shadow DOM 的可访问内容及 slot，避免重复平台。
9. 复杂绘制通过 SurfaceProvider 接入，身份和失效由宿主明确提供。

### FR-03 文字平台与间断（必须）

1. 多行文字按真实分片位置处理，不能把整段文字的外接框顶边当成所有行的支撑面。
2. 在人物邻域按 grapheme / word 边界细化，不改写文本、不插入 span、不破坏选择或复制。
3. 空格与配置的标点作为行为间断；句号、逗号的间断是设计策略，不宣称字形附近没有真实墨迹。
4. 支持中文、英文、混排、组合字符和 emoji；UTF-16 偏移仅用于正确建立 Range，不用于把每个 code unit 当字符。
5. 双向文字按视觉几何位置建立邻接关系，不能简单按 DOM 文本顺序从左往右行走。
6. 字体加载、文本修改、换行和容器尺寸变化后更新平台。
7. `Intl.Segmenter` 不可用时保守降级到较粗文本片段，不冒险切开组合字符；这是待实现要求，当前预览版直接依赖该 API。
8. 普通字墨顶部采用排版与字体度量近似，大字尽量细化为字形顶部的多个可用区间，不能把整段文字布局盒当成实心地面。
9. 文字绘制颜色包括 text-fill-color、透明度和实际背景合成；同色或不可区分的字墨不生成平台，不读取表单值或上传文字。

### FR-04 移动、跳跃与攀爬（必须）

1. 支持走、跑、停、转向、跨、跳、攀爬、坠落、蹲和坐等动作。
2. 走跑具有加减速；步态随相对平台的移动距离变化。
3. 跳跃使用受限的起跳速度与重力，不能用直线瞬移代替跳跃。
4. 大间距目标必须先判断可达性；不可达时选择其他路线、停留、转向或安全坠落。
5. 边框和文字按单向支撑线处理；可区分填充块还形成保守实体边界，参与侧撞、顶头和落地。下跳只临时忽略当前支撑，不能忽略所有下方平台。
6. 攀爬只发生在具有可靠可见边段、可用手脚接触点和可达终点的对象上。
7. 快速运动通过扫掠或受限子步检测，避免穿过薄平台。
8. 落地、支撑失效和边界循环遵守强制安全规则，不能被随机动画或用户触发器跳过。
9. 跳跃只能原地或向面朝方向起跳，反向请求先制动、转身；助跑须通过真实地面加速，不凭空设置远跳水平速度。
10. 冲击较大且平台空间足够时，落地缓冲衔接翻滚再起身或继续行进；窄平台不强行翻滚，墙和动态边缘可以中断翻滚。

### FR-05 动作连贯与扩展（必须）

1. 动作可在允许的接触阶段中断，从当前姿态进行融合。
2. 普通切换不出现骨段长度突变、姿态重置、脚部无意滑动或非设计性位置瞬移。
3. 跳跃、顶点、下降和落地姿态随运动状态变化。
4. 支撑失效可以立即打断坐下、挥手等动作。
5. 首版至少提供 24 个动作定义和 20 类触发机制，详见第 4 节。
6. 自定义动画、动作、触发条件和 SurfaceProvider 通过独立文件与显式注册接入，不要求修改核心状态机。
7. 默认不实现浏览器运行时目录扫描；新增内置算法由静态注册清单接入。

### FR-06 页面滚动和元素移动（必须）

1. 支撑有效时保留平台相对锚点；页面滚动、嵌套滚动和二维平移/正向轴对齐缩放不会重复补偿位置。
2. fixed 与 sticky 平台按实际每帧几何处理，不能统一加上文档滚动量。
3. 空中运动有明确运动参考系；跳跃中滚动页面不会让人物无缘无故变成固定在屏幕上的装饰。
4. 滚动造成离屏时默认隐藏人物并暂停主动游走，保留有效锚点或空中状态；重新进入可视区域后先校验再恢复。
5. 离屏不是平台被删除，也不是自动边界循环的依据。
6. 移动端 pinch zoom、软键盘和可视视口偏移不触发错误重生。
7. 挂载点受到不支持的祖先 transform、perspective 或特殊裁剪影响时，明确提示宿主调整挂载点或提供适配，不静默输出错误坐标。

### FR-07 支撑动态失效（必须）

1. 元素移除、隐藏、祖先折叠、临时绘制消失或来源身份替换，均重新判定当前支撑。
2. 支撑明确失效时，在下一个可执行动画帧释放接触并从最后有效位置坠落。
3. 坠落检测最新下方平台；不存在下方平台时继续至边界并按配置循环。
4. 有无 DOM mutation 不影响当前支撑被优先校验的要求。
5. 虚拟列表复用同一 DOM 节点时，适配器能够区分逻辑身份；不能把新数据对象自动视为旧平台。

### FR-08 人物及宿主交互（必须）

1. 鼠标/Pointer 点击人物位置、靠近或移开时可产生随机反馈。
2. 当前或周围目标元素发生 click、hover、focus 时可以触发反馈。
3. 默认人物覆盖层 `pointer-events: none`；通过人物头部和骨段几何判断点击或靠近。
4. 不调用宿主事件的 `preventDefault()` / `stopPropagation()`，不阻挡按钮、链接、拖动、文字选择和滚动。
5. 同一点击同时命中人物与所在按钮时，宿主行为正常执行；人物动作通过一次仲裁选取，不连续重置多个动作。
6. 触发器有冷却、优先级和进入条件，避免事件风暴导致抖动。
7. 宿主可发送命名为 `custom:*` 的事件接入自定义条件，不伪造核心安全事件。
8. 无需采集或记录输入框值、页面文本和业务数据。

### FR-09 边界循环（必须）

1. 支持横向与纵向循环分别配置，默认启用；横向为左右互通，纵向首版为坠落后从上方进入。
2. 人物自身走出右边界可从左边界进入，反向同理；坠落越过下边界可从上边界继续下落。起跳暂时越过上边界不传送到底部，仍沿原轨迹受重力作用自然回落。
3. 使用当前可视视口边界，但仅人物自身运动越界触发循环；滚动或缩放造成边界变化不能误触发。
4. 循环时清除原支撑、旧目标和旧路径，重新检查另一侧空间。
5. 保留合理方向及速度，并限制最大坠落速度；不保留已经失效的接触。
6. 不强求循环前后屏幕坐标连续，该位置变化是明确的设计事件。

### FR-10 外观设置（必须）

1. 支持人物标称高度、颜色、线宽、内置头型及骨段比例。
2. 默认高度为 18 CSS px、线宽 1.2 CSS px，单色侧向人物；头型提供 circle / square，不添加鼻尖。
3. 修改外观时更新动作包络和碰撞/接触约束，不能只改变绘制而让脚悬空。
4. 默认使用固定骨架拓扑；任意改变骨架拓扑不保证复用全部动作。
5. 自定义颜色和配置只用于受控属性，不拼接可执行代码或任意 HTML。

### FR-11 生命周期和运行安全（必须）

1. 提供创建、异步启动、暂停、恢复、销毁、事件订阅、注册和显式失效通知接口。
2. 重复启动不创建第二个循环；销毁幂等；销毁后的实例不能重新启动。
3. 后台页面暂停动画与主动扫描，恢复时重测并清理累计时间，不补算后台停留时长。
4. 用户主动暂停与页面后台暂停分别保存，页面恢复不能撤销用户暂停。
5. SSR / Node import 以及未启动的实例不得访问 DOM、创建 Worker 或发起网络请求。
6. 销毁时释放覆盖层、观察器、监听器、Range、引用、定时任务、插件资源和可选线程。
7. 模态、fullscreen 或不兼容挂载环境默认避让；不擅自抢占 top layer。

### FR-12 npm 和示例交付（必须）

1. 提供原生 TypeScript 实现、类型声明、ESM 与 CJS 入口，以及无需业务框架的浏览器 ESM 产物。
2. 默认入口包括首版标准预置，默认无运行时第三方依赖。
3. 通过 exports 限定公共入口，扩展按需导入；不导出尚未实现的未来模块。
4. 使用发布文件白名单，不把测试截图、秘密配置或开发缓存打入 npm 包。
5. 提供 `examples/` 单页，演示五个原始场景、移动滚动、属性设置与扩展机制。
6. 示例必须实际使用构建后的包，不复制一份独立人物引擎。
7. 未经用户明确要求不发布 npm，不自动初始化 Git，不上传项目或截图。

## 4. 首版预置数量基线

### 4.1 动作定义：至少 24 个

| 分组 | 动作 ID |
| --- | --- |
| 基础活动（5） | `idle`、`walk`、`run`、`brake`、`turn` |
| 跨越与跳跃（5） | `step-over`、`hop`、`jump`、`standing-long-jump`、`running-long-jump` |
| 下落与落地（4） | `drop-through`、`fall`、`land-soft`、`land-hard` |
| 攀爬（4） | `climb-up`、`climb-down`、`ledge-grab`、`pull-up` |
| 姿态与反馈（6） | `crouch`、`sit`、`stand-up`、`wave`、`look-around`、`recoil` |

允许相关动作复用基础骨架片段，但需要各自明确的运动意图、进入条件和行为表现。不能只改名或把同一动画换色计为多个动作。

### 4.2 预置触发：至少 20 类

`spawn`、`decision-tick`、`edge-approach`、`text-space`、`text-punctuation`、`short-gap`、`long-gap`、`lower-surface`、`support-removed`、`support-hidden`、`actor-pointer-near`、`actor-click`、`host-click`、`host-hover`、`host-focus`、`landing`、`idle-timeout`、`clip-complete`、`viewport-exit-x`、`viewport-exit-y`。

支撑失效和碰撞类触发属于安全机制，不允许随机权重或插件覆盖使其失效。

## 5. 五个原始场景的行为与验收

| 场景 | 环境与操作 | 期望行为 | 必须观察的错误 |
| --- | --- | --- | --- |
| SC-01 文字跨越 | 人物位于混排文字片段顶部，前方有空格、逗号、句号和下一片段 | 走跑到间断前，根据距离跨或跳；落在下一可靠文字支撑线 | 不得站在整段文本外框、把空格视为实体、改写文字或拆开组合字符 |
| SC-02 按钮远跳 | 两按钮间距可调，包括超过当前能力的距离 | 可达时冲刺或立定跳远；不可达时拒绝该路线并选择替代行为 | 不得瞬移、超能力硬跳、穿过途中较高平台或以失败隐藏人物 |
| SC-03 表格下跳 | 人物位于上方单元格，选择下方单元格 | 临时忽略当前支撑并下落，接触下方首个有效支撑 | 不得被原单元格重新捕获，或穿过所有下方单元格 |
| SC-04 悬浮面板消失 | 人物站/坐在悬浮面板上，面板隐藏或移除 | 下一可执行帧释放支撑，自然坠落；有下方平台则落地，否则从上边界循环 | 不得等坐姿播放完再坠落，不得仍引用已移除面板 |
| SC-05 树节点折叠 | 人物位于子节点，用户折叠父节点 | 祖先不可见导致支撑失效，从最后有效位置坠落 | 不得只检查子节点 `isConnected`，不得把折叠后的新位置当作原平台 |

每个场景都必须有可重复的指定初始位置和动作触发方式，不能让验收人员无限等待随机事件。另保留自由随机模式观察整体自然度。

## 6. 非功能需求

### NFR-01 性能（必须）

- 不在每帧全页扫描，不在每帧逐字符建立 Range，不给所有 DOM 节点绑定独立交互监听。
- 一次动画帧中集中读取再写入，避免模块自身造成的反复布局刷新。
- 扫描分片、事件队列、缓存和观察目标均有可配置上限；过载时合并和降级，不无限积压。
- 优先保留当前支撑校验、运动和绘制，再削减远处发现和文字精化。
- 动画时间由 rAF 时间戳驱动，高刷新率不能让人物变快。
- 性能预算属于待实测的验收目标，见第 8 节，不是已验证结论。

### NFR-02 内存（必须）

- 默认小画布，无全屏缓冲、全页截图、无限历史和全页文本副本。
- 定期释放离开邻域的候选、过期 Range 和 DOM 强引用。
- 增长中的页面不导致缓存无限增长。
- 重复创建与销毁后不保留属于实例的活动资源或 detached DOM 引用。

### NFR-03 兼容性（必须）

- 正式目标为实施时 Chromium、Firefox、Safari 当前稳定版与前一主要版本；移动端包括 Android Chrome 和 iOS Safari 当前及前一主要系统版本。
- 具体版本、设备与系统在实施报告记录，不用“适配所有浏览器”代替验证。
- HTML / JS / CSS、React、Vue、Svelte 等 Web DOM 页面使用同一核心；框架层只负责挂载/销毁，不每帧驱动框架状态更新。
- Electron 和 WebView 按实际内核及 CSP 能力评估，不保证所有旧版本或定制内核。
- 核心依赖 DOM、Canvas 2D、rAF、MutationObserver、ResizeObserver 等约定能力；辅助 API 可能力检测后降级。
- 不支持 IE 和非 DOM 原生界面；高级能力不能通过全局 polyfill 强行修改宿主环境。

### NFR-04 可访问性与不干扰（必须）

- 人物默认是装饰，不抢焦点，不在 ARIA live 区域每帧报告。
- 尊重 `prefers-reduced-motion`：保留人物和交互反馈，但默认停止随机游走及持续跳跃；支撑失效仍立即清除接触，随后隐藏并重新寻找稳定位置，不强制播放长距离坠落与循环。完整动作验收在允许完整运动的设置下进行。
- 不改变宿主字体、文本、布局、按钮行为、scroll 行为或业务 CSS。
- 页面模态层或敏感交互需要避让时，可暂停/隐藏自身，不控制宿主组件。

### NFR-05 隐私与安全（必须）

- 默认不联网、不截屏、不上传、不持久化页面内容，无遥测。
- 调试仅记录数值几何、动作 ID、计时和内部来源 ID，不记录输入值或原始文本。
- 插件作为宿主授权 JavaScript 执行，不是沙箱；文档说明其权限与性能责任。
- 不通过 eval、Function、字符串脚本或远程自动加载执行算法。
- 后续视觉扩展必须单独授权，裁剪脱敏，服务端保管密钥，并校验过期结果。

## 7. 后续能力边界

以下项目只保留明确接口或设计说明，不计为首版已实现功能：

1. Worker 数值索引和路线搜索。
2. OffscreenCanvas 或 SVG 正式替代渲染器。
3. 多人物共享世界与性能扩展。
4. 同源 iframe 内部统一坐标桥接、跨域协作协议。
5. 任意 SVG path、图像透明轮廓及复杂裁剪精化。
6. 大模型截图识别插件和模型效果/成本评估。
7. 独立框架包装包及非 Web 平台适配。

宿主通过 SurfaceProvider 提供几何是完整首版拟定的扩展方式；当前预览版尚无公共注册接口，也没有上述高级识别器。

## 8. 性能验收目标草案

所有指标以“单人物、默认外观、截图/Worker 关闭”的条件测量，尚未实测。参考设备需要在第一阶段确定后由用户确认，不能根据开发机结果直接宣布通过。

| 项目 | 建议目标 | 测量限定 |
| --- | --- | --- |
| 默认入口大小 | minified + gzip ≤ 45 KiB | 包含 24 动作及 20 触发；不含声明、示例、可选模块 |
| 普通动画帧模块耗时 | 桌面 P95 ≤ 2 ms；中端手机 P95 ≤ 4 ms | 包含当前支撑测量、物理、姿态和绘制，排除无关宿主执行时间 |
| 同帧追加扫描预算 | 默认 ≤ 2 ms，移动低功耗档 ≤ 1 ms | 单个 DOM API 调用不可抢占，超预算需要记录并调整策略 |
| 模块自身连续任务 | 目标不产生 ≥ 50 ms 的 long task | 对模块导致的强制布局成本也计入分析 |
| 常规页面新增 JS 堆 | 稳定后目标 ≤ 8 MiB | 约 5,000 DOM 节点，最多 1,500 缓存平台；像素/GPU 内存另测 |
| 无宿主重负载的演示 | 60 Hz 设备目标接近刷新率，120 Hz 不加快动作 | 自动数据与真机录屏共同判断，不能保证繁忙宿主下恒定 FPS |
| 资源释放 | 销毁后无实例活动资源与持久强引用 | 垃圾回收时机非确定，不以立即归零的堆读数代替检查 |

坐标误差、接触漂移和标准识别夹具的 precision / recall 门槛见[实施与验收计划](03-实施与验收计划.md)第 6.1 节，同样属于待确认目标，不代表任意网页的准确率保证。

如果第一阶段证明目标互相冲突，应先提交取舍与数据，再修改需求基线；不能在实现后静默降低指标。
