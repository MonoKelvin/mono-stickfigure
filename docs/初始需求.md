# Mono-StickFigure

开发一个“网页火柴人”npm工具包。

根据以下内容先进行调研、分析、决策后制定需求分析方案和详细设计方案等文档。确认无误后才开始编码。

## 需求

网页上随机出现一个小的火柴人，能够智能识别页面上**可见的**任何元素。火柴人可以随机在页面上的任意可见元素上移动。动作包括但不限于：跑、走、跳、爬、坠落、跨、停、蹲、坐等，各种动画都是随机的，并且具有连贯流畅的衔接动画

附件功能：

* 跟随页面滚动、移动等，即相对位置要保持，不能移动、滚动元素的时候位置错乱
* 支持设置火柴人基础属性：大小、颜色、形状
* 支持自定义动画和触发条件（要预制大量已定义的动画和触发机制等）
* 支持响应自身的交互后的反馈，如鼠标点击、移动后的随机事件
* 支持识别周围元素的交互后的反馈，如所在按钮上点击后的动作
* 支持页面循环的路线，比如坠落到页面下边界，可以从页面上边界掉落；往右边界行走，可以从页面左边界出现等。

## 示例

场景1：

当跳到文字行顶部的时候，可以开始跑步，遇到空格、句号逗号等可以跳跃到下个字符串上面

场景2：

遇到两个间距较大的按钮，在按钮1边缘上触发冲刺或者立定跳远到按钮2上

场景3：

遇到表格，在单元格上方触发向下跳跃到下方的单元格

场景4：

火柴人在一个悬浮面板上，突然面板消失，火柴人自然坠落到其他下方的元素上，如果下面没有元素掉落到下边界，则从页面上边界出现。

场景5：

在一个目录树的子节点上，用户点击折叠父节点，所在的元素消失不可见，火柴人自然坠落

## 技术

1. 输出：npm包的形式
2. 测试：提供一个示例目录，里面提供一个页面即可，里面创建各种场景的页面（可以设计成这个npm包的介绍页面），用于演示效果
3. 适配任意html、js、css搭建网页、软件、app前端技术栈，尽量适配全，如果需要特殊对待的技术栈，尽量提取出来独立适配，核心逻辑尽量保证原生前端（如js或者ts）语言编写。适配的代码完善好接口和调用逻辑
4. 代码分模块，尽量独立化设计，比如后续新增新的动画和触发条件的定制化需求可以仅需要新增对应的算法机制文件后，通过注册或者直接放到对应目录即可接入
5. 性能，一些识别、响应、监听等可以设计成后台逻辑，后台实时更新页面状态，反馈到前端人物的动作，保证前端能十分流畅
6. 内存，尽量越少占用内存，一个附加模块尽量不要让原有页面出现明显内存、性能的感知

7. 动画技术方案（重点设计）：可以分析考虑使用哪种方案最好，比如帧动画、canvas实时绘制等，要求评估以下技术要点：风险、性能内存占用、流畅度、扩展（后续追加新动画）

8. 识别逻辑（重点设计）：页面元素太多，各种类型都有可能出现，比如可以停留的平台包括可见的边框、可见的填充块（背景色和当前块颜色差距超过一定比例后认为可以区分）、临时的填充块（比如hover状态才有的高亮色）、文字顶部、线条、图标等等。还有识别的时候可能需要从局部发散到周围等，或者通过大模型截图识别等等，精度越高越好，需要重点设计
